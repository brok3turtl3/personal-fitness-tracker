# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5: Web Search Grounding + Quality Sweep. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **What this phase adds to the UI surface:**
> - **Web-search grounding (RESCH-01..03):** live in-stream search-progress row (D-05), grounded inline footnote markers + a per-message **Sources** list (D-03), the "from research · grounded · linked" source-badge upgrade (D-04), the `webSearchMaxUses` cost cap surfaced in `/settings/ai` (D-06), and the extended citation-link guard (D-09).
> - **Quality sweep (QUAL-01..10):** an **Edit-mode** toggle on the cardio/weight/readings entry forms with per-row Edit buttons (D-11/D-12, QUAL-03); a **70%/95% quota banner** (D-14, QUAL-02); a **multi-tab "data changed elsewhere" banner** (QUAL-04); a **401 "rotate / re-enter key" prompt** (QUAL-07); chat archival lazy-load affordance (D-13, QUAL-05); and the cross-page UX/a11y consistency + color-contrast pass (QUAL-08/09).
>
> **This SPEC extends, does not rebuild, the Phase 4 contract** (`04-UI-SPEC.md`). The chat-message-list `@switch (block.type)` renderer, the confidence/source two-axis badge system, the collapsed `<details>` tool-disclosure, the `isLinkableCitation` allow-list, and the live in-stream tool row are all Phase 4 surfaces this phase reuses verbatim and upgrades at named seams. **Where Phase 4 locked a value, Phase 5 inherits it unchanged unless explicitly noted below.**
>
> **Hard scope rule (from 05-CONTEXT):** No new tracking domains, no goals system, no data import/export feature, no IndexedDB, no Vitest migration. Web search is OFF by default. The 95% prompt offers archive/delete (+ the existing clipboard-JSON safety valve), never a built export feature.

## Typography

Phase 5 introduces **no new sizes** — exactly the **4 sizes** already in the system are used: 14px, 16px, 20px, 28px (plus the pre-existing 12px role-tag micro-label and 11px timestamp in `chat-message-list`, preserved verbatim).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / message / footnote-anchored prose | 16px (1rem) | 400 | 1.5 |
| Inline footnote marker `[n]` | 14px (0.875rem) | 600 | 1.5 (baseline-aligned inline, NOT `<sup>`/`<sub>` size-shrunk) |
| Sources-list item (title + URL) | 14px (0.875rem) | 400 (title 600) | 1.5 |
| "Sources" list heading | 14px (0.875rem) | 600 | 1.2 |
| Web-search progress / resolved summary | 14px (0.875rem) | 600 | 1.5 |
| Source/confidence badge label | 14px (0.875rem) | 600 | 1.2 |
| Edit-mode form header ("Editing entry") | 20px (1.25rem) | 600 | 1.2 |
| History-row Edit/Save/Cancel button | 14px (0.875rem) | 500 (existing `.btn` weight) | — |
| Banner title (quota / multi-tab / 401) | 16px (1rem) | 600 | 1.2 |
| Banner body | 14px (0.875rem) | 400 | 1.5 |
| Page heading h1 (unchanged) | 28px (1.75rem) | 600 | 1.2 |

**Weights used:** 400 (body, banner body, Sources URL, search detail) and 600 (footnote marker, badge labels, headings, Sources title). The single legacy 500 in the global `.btn` class is preserved as-is (Edit/Save/Cancel/banner buttons inherit it) — do not introduce new 500 uses outside `.btn`. This matches the Phase 3/4 two-weight rule.

**Phase 5-specific typography rules:**
- **Footnote marker `[n]` renders at 14px / 600 inline, baseline-aligned — NOT a shrunk `<sup>`.** Per CLAUDE.md a11y ("color is never the only state indicator") and contrast goals, a true superscript would drop below the readable floor and harm contrast; instead the marker is a same-line bracketed numeral styled as a link (accent color, underline-on-hover). This keeps the grounded citation unmistakable and clickable at an accessible size.
- **Sources-list item:** the source **title** at 14px / 600, the `https:` URL at 14px / 400 rendered as a link. Long URLs use `overflow-wrap: anywhere` so they never overflow the bubble.
- **Live search row:** 14px / 600 / 1.5, leading `🔎` glyph as real text content (screen-reader-visible) — matches the Phase 4 tool-disclosure summary voice.
- **Edit-mode form header:** 20px / 600 — re-uses the existing h2-equivalent weight; signals the form is in edit mode (distinct from the default add mode) by copy + this header, never by color alone.
- **A grounded research claim and an un-grounded research claim are distinguished by text + marker presence + badge variant, never by font size alone** (D-04).

## Focal Point Declaration

Each new/changed surface declares one focal point — where a sighted user's eye lands first and where a keyboard user lands after a transition.

| Surface | Focal point | Mechanism |
|---------|-------------|-----------|
| Chat stream **while a web search is running** | The **live search row** (`🔎 Searching the web…`). Stream auto-scrolls to keep it in view (mirrors Phase 4 D-01 tool-progress). No focus steal — focus stays on chat input. | Reuse existing `scrollToBottom()` fired on each `ChatTurnEvent`; `role="status"` `aria-live="polite"`. |
| Chat message **with grounded citations** | The prose answer; the footnote markers `[n]` are inline anchors in DOM order, the **Sources** list foots the message. No auto-focus. | Native `<a href="#source-{msgId}-{n}">` intra-doc anchors. |
| **Edit-mode entry form** (cardio/weight/readings) | The **first form field** (the field the user most likely typo'd) receives focus when Edit is clicked, and the edit-mode header announces the mode change. | `ViewChild` first input `.focus()` on edit-mode enter + `role="status"` announce; Cancel returns focus to the originating row's Edit button. |
| **Quota banner (70% / 95%)** | Announced via `aria-live`; does NOT steal focus from the user's current task. The 95% block banner's primary action (Archive / Delete) is keyboard-reachable in DOM order. | `role="status"` (70%) / `role="alert"` (95%); banner sits ahead of `<router-outlet>` like the recovery banner. |
| **Multi-tab banner** | Announced via `aria-live="polite"`; does NOT steal focus. Refresh action keyboard-reachable. | `role="status"`. |
| **401 rotate-key prompt** | The **"Re-enter key" / "Go to settings" action** is the focal point — it is the user's path out. | `<app-error-state>` `role="alert"`; primary action focusable. |

### Citation guard (D-09) — a render RULE, extends Phase 4 (not user-facing copy)

No user-facing copy. The rule, extended across the full web-on/off matrix (D-09):
- **(a) Web search OFF:** any author-year string (`Smith et al. 2019`), bare DOI, or URL the model writes **in prose** renders as **plain inert text** — never `<a href>`. (Phase 4 behavior, preserved.)
- **(b) Web search ON:** only a structured `web_search_result_location` / `search_result_location` block (via the Phase 4 `isLinkableCitation` allow-list) becomes an `<a>`, and the href is gated to `https:`. Any free-text citation the model writes in prose **still** stays plain inert text.
- `bypassSecurityTrust*`, `innerHTML`, and markdown autolinking of model prose remain forbidden. Verified by the extended adversarial spec (E1, both axes — D-09).

**Specific a11y rules for Phase 5 surfaces:**

| Surface | Rule |
|---------|------|
| Live web-search row | `role="status"` `aria-live="polite"` so a screen-reader user hears `Searching the web…` then `Found {n} sources` — the live-progress promise (D-05) reaches non-sighted users. Native `<details>`/`<summary>` once resolved; `<summary>` accessible name `Show what the AI searched for: {summary}`; 44px touch target. |

| Grounded source badge | `<span>` with `aria-label="Source: from research, grounded in {n} live web source(s)"`; the `· grounded` suffix + `[n]` marker are real text content (screen-reader-visible), not color-only. |

| Quota banner | 70%: `role="status"` `aria-live="polite"` (non-blocking, dismissible). 95%: `role="alert"` `aria-live="assertive"` (write-blocking). Color + icon (`⚠`/`⛔`) + text triple-encode. Actions keyboard-reachable; does not steal focus. |

**Color is never the only indicator (preserved + extended):**
- Grounded research: `· grounded` label + `[n]` marker + `📚🔗` icon (color-neutral chip).
- Quota: `⚠`/`⛔` icon + distinct copy + amber/red.
- Multi-tab: `🔄` + copy (neutral).
- Confidence tiers: color + icon (`✓`/`≈`/`⚠`) + text label (inherited).

**Keyboard navigation rules:**
- Footnote markers + Sources URLs focusable in DOM order; Enter activates and moves focus to the target Sources item.
- Per-row Edit buttons focusable in DOM order; Enter enters edit mode and moves focus to the first form field; Escape/Cancel returns focus to the originating Edit button.
- Banner actions (Refresh / Manage storage / Copy JSON / Dismiss / Go to settings) focusable in DOM order.
- Web-search disclosures focusable in DOM order; Enter/Space toggles (native).
- No custom arrow-key handlers (CLAUDE.md "Function over form").

**Focus management:**
- The loop must NOT yank focus on web-search progress events (mirrors Phase 4) — live progress reaches screen readers via `aria-live`, not focus moves.
- Banners NEVER steal focus (they announce via `aria-live`); the user's current task keeps focus.
- The one intentional focus move is entering edit mode (→ first field) and exiting via Cancel (→ originating Edit button).
