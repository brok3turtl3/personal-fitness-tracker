# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: AI Memory + Tool Plumbing. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Hard scope rule (SC5):** Single-shot chat behavior is preserved. Visible chat UX cannot regress. New visual surface ships dormant — verifiable via Karma + a localhost-only seed button. Real proposals fire in Phase 4.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Angular project — shadcn gate not applicable; React/Next/Vite only) |
| Preset | not applicable |
| Component library | none (standalone Angular components, semantic HTML) |
| Icon library | none — emoji or short text labels are used in-place where icons would normally go (matches existing voice; nav has no icons) |
| Font | `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, Oxygen, Ubuntu, Cantarell, 'Open Sans', 'Helvetica Neue', sans-serif` (declared in `src/styles.css:17–18`) |

**Styling approach (locked from CLAUDE.md):** Minimal custom CSS, semantic HTML, no CSS framework. Each new standalone component carries its own `styles: [...]` array. Existing global utility classes in `src/styles.css` (`.page-container`, `.form-group`, `.btn`, `.btn-primary`, `.btn-secondary`, `.btn-danger`, `.btn-sm`, `.history-list`, `.history-item`, `.empty-state`, `.mt-1..3`, `.mb-1..3`) are reused — Phase 3 introduces no new global classes.

**Existing components to compose (NOT re-implement):**
- `<app-empty-state>` (`src/app/shared/empty-state.component.ts`) — for `/settings/memory` empty state
- `<app-error-state>` (`src/app/shared/error-state.component.ts`) — for storage/save failures on every settings sub-page
- `<app-recovery-banner>` (`src/app/shared/recovery-banner.component.ts`) — for V4→V5 migration failure (already wired through `AppComponent`; no new surface)

## Spacing Scale

Declared values (multiples of 4, derived from existing `src/styles.css` rem usage at 16px root):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Inline badge gaps, error-message margin-top, time-stamp margin |
| sm | 8px (0.5rem) | Compact element spacing — form-group label margin, button gaps |
| md | 16px (1rem) | Default element spacing — form-group margin-bottom, message gap, history-item padding |
| lg | 24px (1.5rem) | Section padding — page-container, h1 margin-bottom, settings-section spacing |
| xl | 32px (2rem) | Layout gaps — main-content padding, side-rail nav width target |
| 2xl | 48px (3rem) | Major section breaks (rare; settings-shell two-column gap on wide viewports) |
| 3xl | 64px (4rem) | Reserved — not used in Phase 3 |

**Exceptions:**
- Mobile breakpoint (`@media (max-width: 768px)`) drops main-content padding from `2rem` to `1rem` and page-container padding from `1.5rem` to `1rem` per existing `src/styles.css:213–222`. New settings-shell side-rail collapses to a horizontal tab strip at this breakpoint (see Component Inventory below).

## Typography

Declared from `src/styles.css` + existing settings-page.component.ts. Phase 3 does NOT introduce new sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (1rem) | 400 (regular) | 1.5 |
| Label / small | 14px (0.875rem) | 500–600 | 1.5 |
| Heading h2 (section) | ~20px (1.25rem default UA) | 600 | 1.2 |
| Heading h1 (page) | 28px (1.75rem) | 600 | 1.2 |

**Weights used:** exactly two — 400 (body) and 600 (labels, headings, history-item-value, role tags). Weight 500 appears once in the existing global `.btn` class and is preserved as-is for backward visual consistency; do not introduce new uses.

**Phase 3-specific typography rules:**
- Pending pill body text: 14px / 400 / 1.5 (matches `.history-item-notes` voice)
- Pending pill action labels: 14px / 600 (button labels, matches `.btn-sm`)
- Memory inspector path-tree node label: 16px / 400 / 1.5 (file-name look)
- Memory inspector path-tree segment depth indent: each level adds `1rem` left padding (visual hierarchy without icons)
- Resolved pending pill timestamp: 12px (0.75rem) / 400 (matches `.message-time`)

## Color

Existing palette preserved (no new hex introduced). 60/30/10 split derived from existing usage:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f5f5` (page background) and `#ffffff` (card surface) | App background, page-container surface, settings sub-page surface |
| Secondary (30%) | `#2c3e50` (text + nav background) and `#ecf0f1` (button-secondary, side-rail surface) | Body text, h1/h2 headings, side-rail nav background, secondary button surface |
| Accent (10%) | `#3498db` | **Reserved-for list below — never "all interactive elements"** |
| Destructive | `#e74c3c` (and hover `#c0392b`) | `<app-error-state>` text, validation errors, Delete-memory-file button hover state |

**Accent reserved for (explicit list — Phase 3):**
1. Active route indicator (`routerLinkActive="active"` in side-rail nav — `#3498db` background)
2. `<form>` input focus border (`border-color: #3498db; box-shadow: 0 0 0 2px rgba(52,152,219,0.2)`) — preserved from existing `.form-group input:focus`
3. Primary submit button: "Save profile", "Save AI settings" (`<button class="btn btn-primary">`)
4. Pending pill primary action: "Save" button (memory write / profile update accept) — uses existing `.btn .btn-primary`
5. Info-note left border (`border-left: 3px solid #3498db`) on the AI-settings privacy explainer and the dev-only seed button container

**Accent NOT used for:**
- Pill chrome itself (uses `#fff` surface + `#ddd` border to match `.history-item` voice)
- Path-tree nodes (default text color)
- Discard / Edit pill action buttons (use existing `.btn-secondary`)
- "Status badge" on resolved pending pills (uses neutral `#ecf0f1` + `#7f8c8d` text)

**State-color rules (not color alone — CLAUDE.md "Accessibility basics"):**
- Resolved pending pill carries BOTH a text label ("Saved", "Discarded", "Edited") AND a leading checkmark/cross/pencil glyph (Unicode `✓`, `✗`, `✎`) — color is never the only indicator.
- Validation-error textareas combine `#e74c3c` border with the existing `.error-message` text below the field.
- Active side-rail item combines accent background with `aria-current="page"` for screen-reader users.

**Path-tree visual treatment (memory inspector):**
- One `<ul>` per directory level; nested `<li>` for sub-paths
- Each level indented `1rem` from its parent
- Leaf nodes (files): `<button type="button">` to toggle inline preview — no separate "expand" affordance, the file IS the toggle

- Active (expanded-preview) leaf: subtle `#ecf0f1` background to visually anchor the preview pane below it
- Keyboard: leaf `<button>` focusable, Enter/Space toggles preview (native button behavior — no custom keymap required)

## Layout & Routing

**Routes added (per D-06, D-07):**
```
/settings              → redirect to /settings/ai (pathMatch: 'full')
/settings/ai           → settings-shell + settings-ai outlet
/settings/profile      → settings-shell + settings-profile outlet
/settings/memory       → settings-shell + settings-memory outlet
```

`settings-shell` is the parent `loadComponent`; the three sub-pages are children registered in the same `loadChildren` block. Hash routing (`withHashLocation()`) preserved.

**Side-rail layout (≥ 768px):**
- Two-column flex: `<aside>` width `200px` fixed; `<main>` flex `1`; `gap: 2rem`

- Active link: `#3498db` background, white text (matches `.nav-links a.active` from `nav.component.ts`)
- Inactive link: `#2c3e50` text, transparent background, hover `#dfe6e9`

- Horizontal tab strip above the `<main>` outlet
- `<aside>` becomes `display: flex; flex-direction: row; gap: 0.5rem; padding: 0.5rem;`
- Active link visual unchanged
- No "drawer" or hamburger menu — three items fit horizontally

**Top nav (`shared/nav.component.ts`) is unchanged.** The single "Settings" link continues to point at `/settings`, which redirects to `/settings/ai` (D-07).

## Accessibility Contract (CLAUDE.md "Accessibility basics" + Phase 1 axe-core gate)

**Every new component asserts `expectNoSeriousA11yViolations(fixture)` after representative render.** Severity gate: `serious | critical` (per Phase 1 D-08 from 01-CONTEXT.md). `color-contrast` rule deferred to Phase 5 QUAL-08 via `disableRules: ['color-contrast']` (matches Plan 01-08 pattern).

**Specific a11y rules for Phase 3 surfaces:**

| Surface | Rule |
|---------|------|
| Settings shell side-rail | `<aside>` with `role="complementary"`; active link gets `aria-current="page"`; visually-hidden h2 announces section |
| All textareas (profile, edit-mode pill) | Explicit `<label>` + `for=` association; `aria-describedby` points to char-counter + error-message |
| Path-tree leaf buttons | Native `<button>` (not `<div role="button">`); `aria-expanded`; `aria-controls` |
| Path-tree directory nodes | Plain text — no role abuse (directories are not interactive) |
| Pending pill | `role="region"` with `aria-label="AI proposal: {kind}"`; resolved badge has `role="status"` + `aria-live="polite"` so screen readers announce when a pending → resolved transition occurs |
| Pending pill action buttons | Native `<button>`; first button (Save) receives focus when pill enters pending state (`autofocus` is unreliable; use `ViewChild` + `setTimeout(() => el.focus(), 0)` matching existing scroll pattern in chat-message-list:118–120) |
| Edit-mode textarea | Receives focus when Edit is clicked; Cancel restores focus to the original Save button |
| Dev-only seed button container | `role="region"` with `aria-label="Developer tools"`; visible status `<p>` confirming localhost-only state |
| Toggle controls (`/settings/ai` redaction) | Native `<input type="checkbox">` paired with `<label>` — NOT custom switches; `<label>` wraps both control and helper text or uses `aria-describedby` to associate the helper |

**Color is never the only indicator (D-13 Phase 1 a11y rule preserved):**
- Active side-rail link: accent BG **plus** `aria-current="page"`
- Validation error: red border **plus** error-message text **plus** `aria-invalid="true"` on the field
- Resolved pending pill: dimmed surface **plus** glyph (`✓` / `✗` / `✎`) **plus** "Saved" / "Discarded" / "Edited" label

**Keyboard navigation rules:**
- Path-tree leaves are focusable in document order (no custom arrow-key handler — out of scope per CLAUDE.md "Function over form")
- Pending pill: Tab through Save → Edit → Discard in DOM order
- Edit-mode pill: Tab from textarea to Save edits → Cancel
- Side-rail: Tab through links in declaration order (AI → Profile → Memory)

**Focus management on pill resolution:**
- After clicking Save / Discard / Save-edits, focus moves to the chat input textarea (the next logical action)
- Spec assertion: `document.activeElement.id === 'chat-input'` after resolve
