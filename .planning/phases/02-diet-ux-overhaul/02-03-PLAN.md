## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input → DietService validation | food macros, density, units, target metrics validated before persistence |
| live SavedFood → historical MealItem render | re-resolution would retroactively mutate logged meals |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | Tampering | snapshot immutability (DIET-09) | mitigate | updateSavedFood never writes mealEntries; logged items read item.snapshot; explicit deep-equal test after a food edit (Pitfall 4, D-12) |
| T-02-03-02 | Tampering | density/target validation bypass | mitigate | validateDensity (>0 finite) + validateDailyTargets (≥0 finite) gate every new numeric input via DietValidationError; calories reuse the 0-20000 range (T-INPUT) |
| T-02-03-03 | Tampering | cross-dimension conversion | mitigate | toBaseUnits delegates to units.ts which throws without per-food density — no global default leaks into the service path (DIET-03) |
| T-02-03-04 | Information disclosure | service egress | accept | DietService adds no network call; all persistence via StorageService chokepoint (T-EGRESS upheld) |
</threat_model>
